# 使用说明

## 启动

1. 在 Edge 登录与根目录 `config.json` 的 `target` 一致的选课系统。
2. 检查 `start_time` 和 `end_time`，填写本次运行的实际日期和时间。
3. macOS 双击根目录的 `先跑自检.command`，自检通过后双击 `一键抢课.command`。
   Windows 对应使用同名 `.bat` 文件。
4. 保持终端窗口与网络连接。结束后到系统“已选课程”页核对结果。

命令行仍使用原来的入口，也可使用包入口：

```bash
uv sync --locked
uv run --locked python grab.py --dry-run
uv run --locked python grab.py
uv run --locked python -m fdu_yjsxk --help
```

`--dry-run` 只检查登录态，不提交课程；`--probe` 会发送一次真实选课请求。
`--now` 仅跳过开始时间，不延长截止时间。

## 配置与运行方式

所有配置都在根目录 `config.json`，字段说明见
[配置示例](../config.example.json)。`courses` 数组按顺位处理，
`enabled: false` 的课程不参与抢课。

当前采用串行流程，`serial_mode: true`：提交一门、取得受理号、查询最终结果，
再处理下一门。返回“已受理”不等于选课成功。

- `request_interval: 0.8`：课程请求之间的间隔。
- `round_interval: 0`：一轮结束后无额外 30 秒等待。
- `full_max_tries: 0`：满额不限次数重试，但仍受截止时间限制。
- `homepage_refresh_secs: 1.0`：在轮次边界按需刷新主页 Token 的最短间隔。
- `cookie_refresh_secs: 240`：定期重新读取浏览器 Cookie。

配置读取后不会热更新。修改配置时，先停止正在运行的脚本，再重新启动。
日志持续追加到根目录 `grab.log`。终端按 Ctrl+C 可停止脚本。

## 常见情况

- 读取 Cookie 失败：确认 Edge 已登录；macOS 终端需要完全磁盘访问权限，
  开启后彻底退出并重开终端。
- 登录过期：在 Edge 重新登录。自动读取 Cookie 不等于自动重新登录。
- 每日数据缓存提示：脚本会按提示等到 13:00，再从第一顺位重试；
  13:00 后仍提示缓存时继续短间隔检查。
- 网络超时或 HTTP 503：脚本进行短暂退避后重试；正常满额不触发此等待。
- 已有受理号但结果未知：继续查询同一受理号，暂不提交其他课程，最终需人工核对。
- 截止时间已过：更新配置；脚本不会自动顺延到次日。

## 开发与文档

代码放在 `fdu_yjsxk/`，入口兼容层仍为根目录 `grab.py`。
离线测试不会读取个人 Cookie，也不会向选课系统发请求：

```bash
uv run --locked python -B -m unittest discover -s tests -v
```
